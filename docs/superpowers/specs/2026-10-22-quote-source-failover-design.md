# 贵金属行情源、自动备援与动态品类设计

## 目标与范围

融通金继续作为首选行情源，并为当前能取得替代行情的品类提供自动备援。美元指数来自外部行情，港金由国际金价和港币汇率计算。后台可配置数据源、基础行情、业务品类、公式、顺序和切换规则，使以后增加品类时无需改动核心报价逻辑。

本阶段包含行情源抽象、自动备援、美元指数、港金计算、动态品类、配置版本和运行状态。前台视觉重做、趋势预测、财经日历、记账及工作需求统计另行设计。

## 核心原则

- 融通金是其已覆盖品类的第一来源。
- 切换只依据连接状态和数据新鲜度，不设置涨跌或价差阈值。
- 同一字段只采用一个来源，不对不同来源取平均。
- 主源恢复并连续产生有效数据后自动切回。
- 全部来源失效时保留最后有效价，并明确显示更新时间和中断状态。
- 每个最终价格都可追溯到实际来源、输入、公式和配置版本。
- 免费公开接口没有服务等级保证，必须由可替换的适配器隔离。

## 三层行情模型

1. **数据源**：融通金、新浪、Yahoo Finance、Frankfurter，以及以后新增的接口适配器。
2. **基础行情**：伦敦金、美元指数、USD/CNH 等未经业务加工的标准行情。
3. **业务品类**：黄金、港金、Au750 等面向报价页面的结果，通过公式引用基础行情或其他业务品类。

公式引擎只读取统一行情键，不感知具体接口。数据源适配器负责把外部数据转换成买价、卖价、最高价、最低价、行情时间和来源状态。

## 数据源和默认优先级

| 基础行情 | 默认来源顺序 |
| --- | --- |
| 伦敦金、伦敦银、伦敦铂、伦敦钯 | 融通金 → Yahoo Finance → 新浪 → 最后有效价 |
| 黄金、白银、铂金、钯金业务基准 | 融通金 → 国际现货换算 → 最后有效价 |
| 黄金 T+D、黄金 9999、白银 T+D | 融通金 → 新浪对应国内行情 → 最后有效价 |
| 美黄金、美白银、美铂金、美钯金 | 融通金 → Yahoo Finance 对应期货 → 新浪 → 最后有效价 |
| 美元指数 | 新浪 → Yahoo Finance → 最后有效价 |
| USD/CNH | 融通金 → Yahoo Finance → Frankfurter → 最后有效价 |
| USD/HKD | Yahoo Finance → Frankfurter → 最后有效价 |
| 港金 | 由伦敦金和 USD/HKD 计算，两项输入各自独立选择健康来源 |

新浪和 Yahoo Finance 是免费公开行情来源，没有稳定性承诺。Frankfurter 无需密钥且可自行部署，但按日更新，只用于汇率校验和最后兜底。后台预留带密钥适配器，未来可接 Twelve Data 或正式授权行情。

管理员可以调整每项基础行情的来源优先级和启停状态。接口字段格式只存在于适配器中，某个免费接口发生变化时无需修改业务公式。

## 自动切换

每个“数据源 + 基础行情”独立维护四种状态：

- `healthy`：持续收到时间和数值均有效的行情。
- `stale`：超过失效时间没有更新。
- `disconnected`：连接或请求失败。
- `disabled`：后台停用。

实时行情默认失效时间为 45 秒，轮询来源可以按周期单独配置。选择器始终取优先级最高的健康来源。主源失效时立即切换；主源恢复后连续收到 3 次有效更新再切回，避免连接闪断导致页面频繁切换。“有效”只检查数值、时间和字段完整性，不检查涨跌幅。

来源切换写入运行日志，包括基础行情、旧来源、新来源、时间和原因。日志仅在程序后台展示和提醒。

所有来源不可用时继续返回最后有效价格，并设置：

```json
{
  "stale": true,
  "sourceMode": "last-known",
  "updatedAt": "真实的最后行情时间",
  "reason": "最后一次失败原因"
}
```

## 换算行情

### 国内克价备用基准

融通金不可用时，可以用国际现货和离岸人民币汇率生成备用参考基准：

```text
人民币克价 = 国际美元/盎司 × USD/CNH ÷ 31.1034768
```

黄金、白银、铂金、钯金分别采用对应国际现货；白银再按业务单位换算。最终销售价和回购价继续套用后台业务公式和基差。此类结果标记 `derived: true`，并记录全部输入来源，不能伪装成交易所原始报价。

### 港金

港金基础价按港币/司马两计算：

```text
港金基础价 = XAU/USD × USD/HKD × 37.429 ÷ 31.1034768 × 成色系数
港金回购价 = 港金基础价 × 回购系数 + 回购基差
港金销售价 = 港金基础价 × 销售系数 + 销售基差
```

成色系数默认 `0.99`，回购和销售系数默认 `1`，两侧基差由管理员根据实际港金市场口径配置。最高价、最低价使用同一交易时段的 XAU/USD 与 USD/HKD 数据计算，不混用不同日期的数据。

预览区显示理论基础价、系数、基差、最终价及两个输入的实际来源，便于校准旧盘口径。

## 后台配置

### 数据源管理

每个数据源包含名称、类型、启停状态、预置连接类型、API 密钥、轮询或心跳周期、超时、失效时间、最近成功时间、最近错误和当前状态。凭据加密保存，读取接口只返回是否已配置。

第一阶段的数据源类型由程序预置。后台不允许填写任意服务器 URL，避免通过配置访问内网。新增全新协议需要开发适配器；已有适配器中的新品类代码可以直接配置。

### 基础行情管理

管理员可以新增基础行情，并配置唯一编号、名称、单位、小数位、多个来源映射、外部代码、买卖高低字段对应关系、来源优先级、是否允许自动切换，以及直接行情或换算公式。

### 业务品类管理

管理员可以新增、复制、删除、停用和排序品类，并配置名称、编号、显示状态、回购/销售/最高/最低公式、小数位和舍入方式。公式可引用已登记的基础行情和业务品类。

保存前必须完成循环引用、缺失引用、除零、字段映射和结果范围检查，并用当前行情即时预览。现有固定 `CATALOG` 迁移到数据库，新增品类不再要求修改代码。

### 版本与回滚

每次保存形成不可变配置版本，记录修改时间、摘要和前后内容。管理员可以预览历史版本并回滚。回滚创建新版本，不删除历史。

## 对外数据

报价结果的每一行增加来源元数据：

```json
{
  "source": "rtj",
  "sourceName": "融通金",
  "sourceMode": "primary",
  "derived": false,
  "updatedAt": "2026-10-22T08:00:00.000Z",
  "stale": false,
  "inputs": []
}
```

换算品类的 `inputs` 列出各输入行情的名称、来源和时间。公开接口不返回数据源密钥、内部连接错误详情或管理配置。

后台接口增加数据源状态与凭据、基础行情映射与优先级、业务品类增删改排序、公式预览、配置版本与回滚、来源切换日志等能力。

## 迁移

首次升级把当前代码中的融通金目录、现有新浪映射和 SQLite 配置迁移到新表。品牌、营业时间、业务公式和后台密码保持不变。迁移在单个数据库事务内执行，升级前自动备份数据库；迁移失败不留下半成品配置。

本地尚未提交的前台脚本和数据源文档不纳入本功能提交。

## 异常规则

- 单一数据源异常不能阻塞其他来源。
- 比当前已采用行情更旧的数据不能覆盖新数据。
- 未来时间、空值、非数字或无穷大数据直接拒绝并记录原因。
- 高低价缺失只影响高低价，不使买卖价整体失效。
- 公式结果的更新时间取所有输入中最旧的时间。
- 港金任一输入失效时，该输入独立切换来源；没有完整输入时保留港金最后有效价。
- 重启后可加载持久化的最后有效行情，但保持过期状态，直到收到新行情。

## 验收标准

自动化验证覆盖：

- 融通金健康时始终优先使用融通金。
- 融通金过期后，有备用来源的行情全部按各自优先级接管。
- 大幅涨跌不会阻止行情接管。
- 主源连续恢复 3 次后切回，短暂恢复不会反复切换。
- 不同基础行情可同时采用不同来源。
- 港金单位换算、成色、系数、基差和舍入正确。
- 动态新增基础行情和业务品类后，无需重启即可预览并生效。
- 循环引用、未知引用、无效映射和除零公式无法保存。
- 配置回滚生成新版本且审计完整。
- 所有来源中断时只显示最后有效价、真实更新时间和中断状态。
- 迁移后在融通金健康时，现有品类结果与升级前一致。

人工验收包括模拟融通金断开与恢复、关闭单个免费来源、修改港金基差、新增一个衍生品类，并在后台核对实际来源和计算链路。

### B. 黄金三品种价差结论（收盘态实测）

- 黄金 T+D ↔ 黄金 9999：价差恒 −0.02 元（T+D 便宜 2 分钱），结构稳定。
- 黄金主行（品牌价 `JZJ_au`）↔ 9999：价差 < 0.3 元，非恒值，盘中需复验定标。
- 结论：黄金 T+D、9999 用新浪直采无缝备援；黄金主行走「9999 + 品牌基差」派生兜底。

### C. 品牌基差已知常量（实测）

- 铂金 9995 与原站对比：回购恒差 1.0、销售恒差 1.36（2026-10-22 采样）。
